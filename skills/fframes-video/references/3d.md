# 3D in fframes videos (`fframes::three_d`)

`fframes::three_d` (the `fframes-3d` crate, feature `3d`) is a three.js style scene graph
with its own renderer. It renders a frame of a 3D scene into an image for an `<image href>`
in the `svgr!` tree, so SVG can go below it, above it and around it like with any image.
Read the crate docs (`fframes::three_d` on docs.rs, or `fframes-3d/src/lib.rs`) for the full
API and the three.js name of every type.

Use 3D when depth, light or a moving camera is the point: a product shot, a device that
assembles, a logo in a real material, a camera move through a set. Titles, cards, charts and UI
stay SVG: they are sharper, cached across frames and much cheaper. A good 3D video usually is
an SVG video with one or two 3D shots, or a 3D shot with SVG text over it.

The repository's [arm example](https://github.com/dmtrKovalenko/fframes/tree/main/examples/arm)
is a 37 second film that uses most of the crate. Its `src/effects.rs` builds camera shake, a
light beam in hazy air, spark streaks and a printed grid from the building blocks.

## Setup

```toml
[dependencies]
# `3d`: fframes::three_d; `wgpu`: the 3D renders on the GPU
fframes = { version = "<the version of fframes>", features = ["3d", "wgpu"] }
```

| backend of the video | where the 3D renders |
| --- | --- |
| Skia on Vulkan (Linux, Windows) with `fframes_skia_renderer = { features = ["vulkan", "wgpu"] }` | on Skia's own GPU device. The 3D frame is a texture that Skia draws in place, nothing is read back |
| Skia on Metal (macOS), Skia on Vulkan without `wgpu` | on the GPU through wgpu (Metal, Vulkan, DX12), read back as pixels (a few ms per 1080p frame) |
| the CPU backend, or no usable GPU | the CPU rasterizer, 60 to 150 ms per 1080p frame on 28 threads |
| the web editor (wasm) | the CPU rasterizer at half size |

Without the `wgpu` feature everything renders on the CPU. `Renderer::cpu()` forces the CPU for
one renderer. With a GPU, a 1080p frame with shadows, reflections, depth of field and 4x
MSAA takes 5 to 20 ms on an integrated GPU; the arm film (2216 frames) renders in 14 s on an
M4 Max.

## The pattern: build once, pose per frame

```rust
use fframes::three_d::*;

pub struct ProductShot {
    scene: Scene,
    hinge: NodeId,
    renderer: Renderer,
}

impl ProductShot {
    pub fn new() -> Self {
        // Everything heavy happens once: geometry, textures, fonts, models.
        let mut scene = Scene::new()
            .environment(Environment::studio())
            .background(Background::Transparent); // the SVG behind shows through
        let body = scene.add(
            Node::mesh(Geometry::rounded_box(1.2, 0.5, 0.8, 0.06, 4), Material::metal(0xc9ccd1, 0.3))
                .at(0.0, 0.25, 0.0),
        );
        // A group at the back edge is the hinge: the lid turns around it, not its center.
        let hinge = scene.add_to(body, Node::group().at(0.0, 0.25, -0.4));
        scene.add_to(hinge, Node::mesh(
            Geometry::rounded_box(1.2, 0.08, 0.8, 0.03, 3),
            Material::standard(0xff4a00).roughness(0.35).clearcoat(1.0),
        ).at(0.0, 0.04, 0.4));
        // Only shadows: the floor itself stays invisible over the SVG background.
        scene.add(Node::mesh(Geometry::floor(20.0, 20.0), Material::shadow_catcher(0.5)).shadows(false, true));
        scene.add(Node::light(Light::sun(Rgb::WHITE, 2.5, vec3(2.0, 6.0, 3.0))));
        let renderer = Renderer::new(1920, 1080).tone_mapping(ToneMapping::Neutral).bloom(Bloom::default());
        Self { scene, hinge, renderer }
    }

    pub fn image(&self, t: f32, open: f32) -> fframes::media::ImageData<'static> {
        // Per frame: clone (the geometry is shared by `Arc`), pose, render.
        let mut scene = self.scene.clone();
        scene[self.hinge].rotation = euler(-open * deg(70.0), 0.0, 0.0);
        let camera = Camera::perspective(30.0)
            .orbit(vec3(0.0, 0.3, 0.0), 4.5, 25.0 + t * 8.0, 18.0)
            .focus_on(vec3(0.0, 0.3, 0.0), 4.0);
        self.renderer.render(&scene, &camera)
    }
}
```

In `render_frame`: `let image = self.shot.image(t, frame.animate(&self.open));` then
`<image href={image.href()} x="0" y="0" width="1920" height="1080" />`.

- Y is up, the camera looks down -Z, units are meters, angles are radians (`deg()`,
  `euler_deg()`). Hex and `&str` colors are sRGB. Multiply an `Rgb` above 1 for light that
  blooms (`Rgb::hex(0x22e8ff) * 6.0`).
- Keep the `NodeId`s of everything you animate. A child turns around its parent's origin, so
  put a group where the pivot is (a hinge, a joint). Set `position`, `rotation`, `scale`,
  `visible`, a material's `emissive_intensity` or `opacity`, or a light's `intensity_mut()`.
- Drive poses and the camera with the same tools as the SVG: `frame.animate(&timeline)` with
  `f32` values, springs, and the time constants the sound uses. A turntable is
  `orbit(target, distance, azimuth_degrees, elevation_degrees)` with an animated azimuth.
- `Camera::focus_on(point, blur)` adds depth of field (blur in pixels at 1080p; 4 to 9 is
  natural, 16 is macro). `Renderer::render_motion_blur(3, |o| build(t + o * 0.5 / FPS))`
  blurs fast shots with a half open shutter; use it only where things move fast.

## Composing 3D with the rest of the video

- **Layers.** `Background::Transparent` (the default) lets the SVG behind show through, so
  gradients, photos and brand backgrounds stay SVG. `Material::shadow_catcher` on a floor
  keeps only the shadows, and the object sits on the SVG. Text and UI go above the `<image>`.
- **Insets.** A 3D object in part of the frame gets a renderer of that size
  (`Renderer::new(600, 600)`) and `<image x=.. y=.. width="600" height="600">`. Do not render
  a full frame for a small box.
- **SVG on 3D.** `camera.project(world_point, w, h)` gives the pixel of a 3D point in the
  renderer's image (`None` behind the camera) and `camera.pixel_size(point, meters, h)` sizes
  a bracket. Add the `<image>`'s `x`/`y` and scale by `width / w` when the image is not full
  frame. `scene.local_to_world(id, local)` and `scene.world_position(id)` find the point on an
  animated node. Labels then stay on the object while the camera moves.
- **Transforms, clips, opacity.** The `<image>` is an image: `opacity`, `transform`,
  `clip-path` and masks apply to it like to a photo, also on the GPU path. Cross-fade or wipe
  a 3D shot with them.
- **Scenes.** Put a 3D shot in its own `Scene` and keep its `Scene` and `Renderer` in the
  struct. `ctx.render_scenes` renders only the scenes that are on screen; during an
  `Overlap` both scenes render, so two 3D shots that overlap cost two renders.
- **Media in 3D.** `Texture::from_image(&image)` puts an fframes image on a material
  (`.map(texture)`, `.emissive_map(texture)` for a glowing screen). For a video playing on a
  screen, make a new texture from each synced frame, resized to the screen first.
- **Fonts and models.** `Geometry::text(include_bytes!("../media/Inter.ttf"), "Hi", 0.5, 0.1,
  0.01)?` (size, depth and bevel in meters) makes extruded text from the same font file as
  the SVG. `Model::from_gltf(include_bytes!(..))`
  loads a `.glb` (`model.add_to(&mut scene, None)` returns an instance; `instance.play(&mut
  scene, clip, t)` animates it, `instance.root` moves it). STL files are often millimeters with
  Z up: `Geometry::from_stl(bytes)?.scale(0.001, 0.001, 0.001).rotate_x(-FRAC_PI_2)`.
- **Matching the look.** Pick one lighting setup per video: `Environment::studio()` for
  products, an HDR panorama (`Environment::map`) for real places. `ToneMapping::Neutral`
  keeps brand colors, ACES (the default) is filmic and shifts saturated colors. Match the SVG
  palette with `fframes::Color::from(rgb)` of the material colors.

## Do

- Build geometry, textures, models and text in the constructor. The GPU caches meshes and
  textures by their `Arc`; new ones every frame upload again every frame.
- Clone the scene in `render_frame` and change only what moves.
- Set `.shadows(false, ..)` on floors, walls and far scenery and give `Shadow::bounds` a box
  around what casts shadows, so the shadow map stays sharp. Only `Light::sun` (or
  `Light::with_shadow`) casts shadows; point and spot lights shine through objects.
- Use `Reflector::floor()` with `Material::reflection(..)` and a roughness map for polished
  floors, one reflector per scene.
- Give small glowing particles a few pixels of size, or keep them in focus: out of focus, a
  very bright single-pixel dot turns into a pattern of dots in the depth of field.
- Look at the result: `strip` and `frame` show the 3D as pixels; `inspect` cannot see inside
  the 3D image, but `inspect --pops` still finds objects that appear or vanish in one frame.
  A renderer with `.cpu()` draws the same shot on the CPU rasterizer to compare.
- Make random things deterministic: hash the frame or the index, never use time or a random
  number generator, because frames render out of order on several threads.

## Do not

- Do not use 3D for flat things (text cards, charts, UI) or as decoration that has nothing to
  do with the subject. A spinning logo for no reason is slop.
- Do not shake or zoom the camera on every beat, or move it all the time. Hold, then move with
  a purpose; small camera shake only on real impacts.
- Do not read files, decode models or build geometry in `render_frame`.
- Do not render a huge floor with shadows from the whole world in the shadow map: shadows get
  blurry and blocky.
- Do not draw gradients or vignettes in 3D: put them in SVG behind or above the transparent
  3D image.
- Do not expect real volumetric light. `Fog`, a glowing cone (`Material::glow` on nested
  cones, as in `examples/arm/src/effects.rs`) and particles inside the beam look like haze.
- Do not render motion blur, high sample counts or 4K 3D in the web editor: it renders on the
  CPU. Check `ctx.mode` (`FFramesMode::Renderer`) to turn expensive parts on only for renders.

## Building blocks

| three.js | `fframes::three_d` |
| --- | --- |
| `Scene`, `Group`, `Mesh`, `InstancedMesh`, `Points` | `Scene`, `Node::group`, `Node::mesh`, `Node::instanced`, `Node::particles` |
| Box, Sphere, Cylinder, Cone, Capsule, Torus, Plane, Circle, Ring, Lathe, Extrude, Tube, Icosahedron, Text, RoundedBox geometry | `Geometry::cuboid`, `sphere`, `cylinder`, `cone`, `capsule`, `torus`, `plane`, `floor`, `circle`, `ring`, `lathe`, `extrude`, `tube`, `icosahedron`, `text`, `rounded_box`; `merge`, `translate`, `rotate_*`, `scale`, `smooth`, `flat` |
| `MeshStandardMaterial`, clearcoat, `MeshBasicMaterial`, `ShadowMaterial`, `MeshNormalMaterial` | `Material::standard`, `metal`, `.clearcoat`, `unlit`, `glow` (additive), `shadow_catcher`, `normals` |
| `map`, `normalMap`, `aoMap`, `emissiveMap`, metal-roughness map | `.map`, `.normal_map`, `.ao_map`, `.emissive_map`, `metal_rough_map`; `Texture::decode`, `from_fn`, `from_image` |
| `AmbientLight`, `HemisphereLight`, `DirectionalLight` + shadow, `PointLight`, `SpotLight` | `Light::ambient`, `hemisphere`, `directional`, `sun`, `point`, `spot` |
| `RoomEnvironment`, `RGBELoader`, `Fog`, `FogExp2`, `Reflector` | `Environment::studio`, `Environment::map`, `Fog::Linear`, `Fog::Exp2`, `Reflector::floor` |
| `GLTFLoader` + `AnimationMixer`, `STLLoader` | `Model::from_gltf`, `ModelInstance::play`, `Geometry::from_stl` |
| `UnrealBloomPass`, `BokehPass`, tone mapping | `Bloom`, `Camera::focus`, `ToneMapping::{Aces, Neutral, Linear}`, `Renderer::render_motion_blur` |
| `vector.project(camera)` | `Camera::project`, `Camera::pixel_size` |
